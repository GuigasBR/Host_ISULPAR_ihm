2. Engenharia de Requisitos

Elicitação e análise de requisitos

A Engenharia de Requisitos é uma área da Engenharia de Software responsável por compreender, identificar, documentar e gerenciar as necessidades relacionadas a um sistema.
Um requisito representa uma condição ou capacidade necessária para que um usuário alcance determinado objetivo ou para que um sistema atenda a uma necessidade, contrato ou especificação.

A elicitação e a análise são atividades iniciais desse processo.

Elicitação é a atividade de descobrir e levantar as necessidades dos clientes, usuários e demais envolvidos no projeto.

Análise consiste em examinar os requisitos identificados, classificá-los, organizá-los, definir prioridades e negociar possíveis conflitos.

Técnicas utilizadas

Algumas técnicas utilizadas são:

  • Entrevistas com clientes e usuários.
  • Análise de documentos existentes.
  • Observação das atividades realizadas pelos usuários.
  • Criação de protótipos.
  • Elaboração de cenários.

Durante esse processo, podem surgir dificuldades, como necessidades pouco claras, opiniões diferentes entre os envolvidos, mudanças no ambiente de negócio e solicitações difíceis de implementar.

Por isso, é importante conversar com diferentes participantes do projeto e compreender o contexto em que o sistema será utilizado.

Requisitos funcionais

Os requisitos funcionais descrevem as funções e funcionalidades que o sistema deve oferecer.

Eles indicam o que o software precisa fazer para atender às necessidades dos usuários.

Exemplos:

  • O sistema deve permitir o cadastro de usuários.
  • O sistema deve disponibilizar uma ferramenta de pesquisa.
  • O sistema deve permitir o registro de informações.

Requisitos não funcionais

Os requisitos não funcionais, também chamados de requisitos de qualidade no material estudado, descrevem características relacionadas à qualidade e ao funcionamento do sistema.

Eles complementam os requisitos funcionais, estabelecendo condições que o software deve atender.

Exemplos:

  • O sistema deve permanecer disponível 24 horas por dia.
  • A pesquisa deve ser concluída em menos de cinco segundos.

Requisitos de restrição

Além dos requisitos funcionais e não funcionais, o material apresenta os requisitos de restrição.

Eles estabelecem limitações que restringem as possibilidades de desenvolvimento da solução.

Exemplos:

  • O sistema deve ser desenvolvido para a plataforma web.
  • O projeto deve utilizar uma linguagem de programação específica.
  • O banco de dados deve seguir uma tecnologia determinada pela organização.

Casos de uso

Os casos de uso representam as funcionalidades de um sistema a partir da perspectiva dos usuários ou de outros elementos externos que interagem com ele.

Eles ajudam a demonstrar quem utiliza o sistema e quais atividades podem ser realizadas.

Um caso de uso pode ser descrito por meio de um diagrama ou de uma especificação textual, apresentando o funcionamento da interação.
